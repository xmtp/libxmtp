# Historical CI profile

The sample contains 722 workflow runs. It covers 60 `self-hosted` push heads from 2026-09-30 to 2026-10-06, and 40 PR head commits from 2026-10-05 to 2026-10-06. The collector read 10 pages of push run metadata, 10 pages of PR run metadata, and 200 PR records with base `self-hosted`. It then read job and step metadata. It did not read logs or change GitHub state. All 722 job requests succeeded.

Do not use the historical median as the current configuration baseline. Commit `4e63f8edd5` changed the platform matrix at 2026-10-06T19:36:02Z. Commit `e09d535c17` changed SDK generation and lint at 2026-10-06T20:21:33Z. The latter epoch has five push heads. Four were complete at collection time. Only one Lint run and one Test run succeeded. The small epoch has no reliable median estimate for those workflows.

## Time

Gate time is workflow `created_at` to the final aggregate `Lint` or `Test` job completion. For other workflows it is `created_at` to the last assigned job completion. Execution span is first assigned job start to gate completion. It includes waits between jobs. Initial queue time is `created_at` to first assigned job start. Step duration is the API step start to step completion. These data do not split a compound command into build, service wait, and test execution.

| Test gate | 30.60 min | 17 | 1.87 min | 20 |

The PR Test median is a survivor bias. Eleven of twenty successful runs did not execute a Blacksmith job with material cost. The nine successful PR Test runs that did execute material work had a **41.10 minute median**. There were 25 canceled and six failed PR Test runs. There were 30 canceled and twelve failed push Test runs. Cost analysis includes canceled heads. A successful-only time median cannot show time to merge for those heads.

Push Lint execution span was 14.08 minutes at the median. Its initial queue was 0.07 minute. Push Test execution span was 29.82 minutes. Its initial queue was 0.10 minute. PR Lint execution span was 17.43 minutes; its initial queue was 0.27 minute. PR Test initial queue was 0.82 minute, with a 10.15 minute p90. Thus queue reduction alone cannot meet either target for a substantive change.

## Allocated cost

Core minutes are **assigned runner job duration multiplied by the runner's vCPU count**. This is allocated runner time, not measured CPU use and not billing cost. The report maps only explicit `blacksmith-Nvcpu-*` labels. It does not guess the capacity of `warp-macos-15-arm64-6x`, `warp-macos-26-arm64-12x`, `macos-15`, `windows-latest`, `ubuntu-latest`, or `ubuntu-24.04-arm`. Their allocated runner minutes are shown separately. A runner-capacity JSON file can add stated assumptions with `--cores-json`.

The core workflow subtotal has a 4,222.87 median for pushes and a 3,412.70 median for PR heads. The PR scope also includes Cargo-Deny Checker and Publish backend image.

The latest successful example allocated at least 501.53 core minutes for Lint and 4,194.67 for Test. In that Test run, the façade job used 565.33 core minutes, recovery used 402.93, Android staging used 317.60, and four browser shards together used 1,070.40. These jobs account for 56.2% of known Test allocation. Their source and test commands need further analysis before a coverage claim.

Canceled workflows consumed 89,947.33 known core minutes in the push cohort, or 35.8% of the cohort total. They consumed 76,054.73 in the PR cohort, or 53.3%. Thirty-two of fifty-nine complete push heads and nineteen of forty PR heads had at least one canceled workflow. Canceling earlier, or avoiding broad work that cannot finish between pushes, can reduce cost without removing tests.

## Repeat work and limits

- No source SHA was shared between push and PR event cohorts. Merge commits have different SHAs. Sixteen merged PRs had both sampled PR branch runs and sampled base push runs. `paired-pr-push.json` lists their costs. That is repeated validation after merge. It also has a cache-warming and merged-tree purpose; do not call it unnecessary without replacing that purpose.
- There were 71 extra workflow run records at repeated PR source head SHAs. They are not all proven redundant. A changed merge base can require a new run at the same source SHA.
- Only eighteen sampled PR workflow records retained a PR association in the run API. The other 284 records use matching PR head branch metadata from PRs whose current base is `self-hosted`. This is an inferred cohort. The API association is often empty after merge. A branch name can be reused, or a PR base can have changed.
- Nine sampled workflow runs had attempt 2. The job requests use `filter=latest`. Earlier attempt cost is omitted. This makes the cost lower bound smaller. A billing-grade report must collect each earlier attempt too.
- Time statistics use completed successes. They exclude canceled waits and retries. `finished_gate_minutes` in the JSON also includes failures. Full-head cost includes failed and canceled latest attempts, and excludes heads with an active sampled run.
- Job API results are a snapshot. One newest push head was still active. The selected run metadata does not update during collection.
- GitHub caps filtered run queries at 1,000 records. The collector uses the latest 1,000 records in each event query; it is not a complete repository history.

## Files and validation

- `dev/ci/ci-history-collect.py`: repeatable metadata collector. Read-only GitHub API calls. Output includes raw run metadata, PR metadata, and job metadata.
- `dev/ci/ci-history-analyze.py`: offline analyzer. `--since ISO_TIMESTAMP --output-prefix current-` isolates a configuration epoch. `--cores-json FILE` supplies explicit capacity assumptions.
- `/tmp/test-ci-history-analysis.py`: independent fixture for cost, canceled allocation, unknown capacity, and aggregate timing. It passed. A temporary mutation that set known runner capacity to zero caused the expected assertion failure.
- `/tmp/ci-history/summary.json`, `run-metrics.json`, and `head-metrics.json`: full sample outputs. `current-summary.json`, `current-run-metrics.json`, and `current-head-metrics.json`: the epoch outputs.
- `/tmp/ci-history-summary-all.json`, `/tmp/ci-history-summary-current.json`: separate snapshot copies for transfer.

Example collection: `python3 ci-history-collect.py --repo xmtp/libxmtp --base self-hosted --output /tmp/ci-history --push-count 60 --pr-count 40`.

Example current epoch analysis: `python3 ci-history-analyze.py --input /tmp/ci-history --since 2026-10-06T20:21:33Z --output-prefix current-`.
