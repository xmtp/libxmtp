# iOS SDK 4.12.0

## Breaking changes

Push notifications now use the self-hosted backend. `XMTPPush`, the generated
notification-service stubs, `getPushTopics`, and `allPushTopics` are removed.
The example app no longer registers for push notifications. The SDK depends
directly on SwiftProtobuf and no longer depends on Connect.

Apps must call `client.enableNotifications(config)` to register again. Previous
subscriptions and per-conversation notification choices are not migrated. The
new default selects active conversations with allowed consent, includes welcomes,
and excludes sync groups and commits.

Rewrite the notification receiver. APNs sends a background payload with a base64
wire topic and a decimal-string `sequence_id`. It contains no encrypted message
or alert text. Fetch and decrypt the envelope through the SDK before display,
and suppress duplicate notifications. Do not use the old string routing topics.

The backend operator owns cleanup of the old notification server and its stored
registrations. `disableNotifications()` cannot unregister from the old server.
Old pushes can continue until the operator completes that cleanup.

## New API

Use `Client.enableNotifications`, `Client.disableNotifications`, and
`Client.notificationState`. `Group`, `Dm`, and `Conversation` expose
`setNotifications` and `notificationsEnabled`. `.default` resets an override to
the configured consent rules. `.failed(error)` contains a typed
`NotificationError`. All five methods use `async throws`.

See the [shared push guide](../../../apps/docs/src/content/docs/sdk/push-notifications.md)
and [backend configuration](../../../apps/docs/src/content/docs/get-started/push-configuration.md).
