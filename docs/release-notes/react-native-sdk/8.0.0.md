# React Native SDK 8.0.0

These notes are prepared for RC validation. Installed-package native runtime,
compatibility, and migration checks must pass before final publication.
The npm trusted publisher must point to the libxmtp release workflow before
publication. Dry runs do not prove that external account setting.

No stable React Native SDK tag exists in this repository. The comparison
baseline is the first repository root commit, following the first-release
notes policy. This baseline is not a previous published React Native version.

## Highlights

- Package ownership moves to libxmtp under `@xmtp/react-native-sdk`.
- The public API follows the generated native SDK 8 API.
- The package includes the native Rust libraries. Consumers do not need Rust or Nix.
- Optional React helpers live under `@xmtp/react-native-sdk/react`.

## Breaking Changes

Every pre-8.0.0 consumer must migrate. Previous React Native signatures and
option shapes are not compatibility targets. Use the legacy database-to-archive
converter and normal archive import within the converter's supported schema
range. The package does not adopt a legacy database automatically or preserve
installation keys or network identity through conversion.

The native module requires Hermes and React Native New Architecture. Expo
requires a development build; Expo Go cannot load this native module. The
release support matrix must list only platform/version pairs that passed
installed-package native runtime checks.

Apps own secret-key persistence, token acquisition, OS permissions, and media
selection. End SDK clients and readers when their owners finish. JavaScript
cannot process notifications while the OS has suspended or terminated it;
native background and cold-start handlers require app integration.
