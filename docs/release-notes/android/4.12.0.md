# Android SDK 4.12.0

## Breaking changes

Push notifications now use the self-hosted backend. `XMTPPush`, push preferences,
the generated notification-service stubs, `getPushTopics`, and `allPushTopics`
are removed. The example app no longer registers for or receives pushes.

Apps must call `client.enableNotifications(config)` to register again. Previous
subscriptions and per-conversation notification choices are not migrated. The
new default selects active conversations with allowed consent, includes welcomes,
and excludes sync groups and commits.

Rewrite the notification receiver. Pushes contain a base64 wire topic and a
decimal-string `sequence_id`; they do not contain `encryptedMessage` or the old
string routing topic. Fetch and decrypt the envelope through the SDK before
display, and suppress duplicate notifications.

The backend operator owns cleanup of the old notification server and its stored
registrations. `disableNotifications()` cannot unregister from the old server.
Old pushes can continue until the operator completes that cleanup.

## New API

Use `Client.enableNotifications`, `Client.disableNotifications`, and
`Client.notificationState`. `Group`, `Dm`, and `Conversation` expose
`setNotifications` and `notificationsEnabled`. `NotificationOverride.Default`
resets an override to the configured consent rules. Failed state contains a
typed `NotificationError`.

See the [shared push guide](../../../apps/docs/src/content/docs/sdk/push-notifications.md)
and [backend configuration](../../../apps/docs/src/content/docs/deploy/push-configuration.md).
