# Android SDK 8.0.0

These notes are prepared for RC validation. Final package installation and
migration checks must pass before the final release.

## Highlights

- Import generated public types from `uniffi.xmtp_sdk` and use `SDKClient`.
- The Maven coordinate remains `org.xmtp:android`.
- The package contains the generated Kotlin types and Android native libraries.

## What's Changed

Version 8 uses the generated SDK API and the self-hosted backend contract.
The backend does not join or copy the previous XMTP network. All participants
must use the same deployment. Pass an explicit backend URL; there is no default
network or fallback endpoint. Read the
[self-hosted migration guide](../../../apps/docs/src/content/docs/get-started/migrate-to-self-hosted.mdx)
before moving users. The
[generated API migration guide](../../self-hosted/sdk-migration/README.md) has a
Android example for client API changes.

## Breaking Changes

- Update calls to the generated Kotlin names. No rename aliases are provided.
- Object members such as `inboxId()` are methods. Timestamps use `Timestamp`.
- Use `client.conversations.streamAllMessages()` or `group.streamMessages()` as a Kotlin Flow.
- Resolve storage with the Android app context before calling `create` or `build`.
- Use per-client `ContentCodec` values. Legacy codec adapters are removed.

When moving from the previous XMTP network to a new deployment, preserve
required history with the old SDK and create a new local database. The old
network database does not move users or conversations to the new deployment.

For an API upgrade within the same self-hosted deployment, the default storage
layout has changed. End the old client before opening the new client. To reopen
an existing database, pass its actual path and an attachments directory through
explicit storage. Keep the existing encryption key on native hosts. A new
default path does not move the old database.

`create` can establish an identity. `build` opens an existing stored identity
and fails on an empty database. End clients and readers with `end()`.

## New Features

- Typed client events, content errors, and attachment transfer errors.
- Message delivery cursors for replay after a saved position.
- Explicit offline opening with saved identity and storage information.
- Per-client codec registration and typed content operations.

## Bug Fixes

The migration guide records storage reopen, reader shutdown, and codec
migration behavior. Validate these paths with the installed RC package and
the intended backend before accepting the release.
