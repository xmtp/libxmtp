# Node SDK 6.1.1

A patch release for the 6.1 line. It depends on `@xmtp/node-bindings` 1.11.1.

## Highlights

- **Ended streams stay ended.** A stream retry that was already scheduled can no longer reopen a stream after `end()`. Agents that restart their streams after an error no longer get each message more than once.
- **TCP keep-alive no longer races the HTTP/2 PING.** The idle time before the first probe is now 60 seconds, and the probe interval is always set. This targets idle streams that were reset about every 35 seconds on Windows.
- **The maximum group size is now 500 members** (was 250).

## Bug Fixes

### Ended streams no longer reopen

In 6.1.0, a stream that lost its connection scheduled a retry. Calling `end()` (or `return()`) did not cancel that retry, so the stream reopened later with nobody holding it and kept calling `onValue`. The Agent SDK ends and recreates its streams after every stream error, so each error added another copy of the stream, and each message was delivered once per copy.

In 6.1.1, `end()` and `return()` are final:

- A pending retry is cancelled, and no new stream is opened.
- `onValue`, `onError`, `onFail`, `onRetry`, and `onRestart` are not called after `end()`.
- A stream that was still starting when `end()` was called is closed as soon as it opens.
- At most one retry runs at a time.

Other behavior changes in stream recovery:

- A stream that fails while it is starting now counts against `retryAttempts`. After `retryAttempts` consecutive failed starts, the stream ends with `StreamFailedError`. In 6.1.0 these failures reset the retry count, so the stream retried forever.
- A restart that comes up healthy still resets the retry count, so a long-running stream keeps recovering from occasional disconnects.
- `onFail` is no longer called for a close from an older, already replaced stream.
- If `onRestart` throws, the error goes to `onError`. It no longer starts a second retry.

### TCP keep-alive

From `@xmtp/node-bindings` 1.11.1: the TCP keep-alive idle time is now 60 seconds (was 16 seconds), and the probe interval is always 10 seconds. The HTTP/2 PING (every 16 seconds, 10 second timeout) still detects a dead connection. TCP keep-alive is now only a backstop for connections that carry no PINGs. Before this change, Windows received a keep-alive probe interval of 0. `XMTP_GRPC_TCP_KEEPALIVE_SECS` still sets the idle time, and `0` disables TCP keep-alive.

## Other Changes

### Maximum group size raised to 500

Groups can now have up to 500 members. The limit is checked when you add members by identifier (`group.addMembersByIdentifiers`, `conversations.createGroupWithIdentifiers`).
