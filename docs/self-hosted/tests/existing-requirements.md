# Existing Test Requirements

This catalogue describes the requirements expressed by tests in the `libxmtp` source tree at commit `cc878025dab2` on 2026-09-01.

It records current test intent. It does not grade tests or recommend changes.

## How to read this catalogue

Each requirement has a stable ID and four fields:

- **Subject:** The module, method, function, API, or system behavior under test.
- **Expectation:** The behavior that the tests require.
- **Preconditions:** The setup or prior state that the behavior needs.
- **Parameters:** The input classes, values, states, and boundaries that the tests use.

Tests share one requirement when they require the same observable behavior, setup class, and input class. A shared requirement can cover more than one crate, binding, or SDK when those tests express the same contract. Distinct failure, boundary, security, platform, and state-transition behavior has a separate requirement.

Parameterized cases, loops, target matrices, and macro expansions are summarized in the Parameters field. The three manual scenarios use separate `MANUAL-REQ` IDs.

## Maintenance rules

- Do not reuse an active or retired ID for another contract.
- Keep gaps in each ID namespace. Add a new ID above that namespace's prior maximum.
- Update this file and the test index in the same change.
- Reuse a requirement when a test changes only its representative values.
- Add a requirement for a distinct behavior, failure, boundary, security rule, or state transition.
- Remove a requirement only after no index row references it.
