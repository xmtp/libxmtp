The first step to creating a conversation is to verify that participants' identities are reachable on XMTP. The `canMessage` method checks each identity's compatibility, returning a response indicating whether each identity can receive messages.

Once you have the verified identities, you can create a new conversation, whether it's a group chat or direct message (DM).

## Check if an identity is reachable

`Client.canMessage(identities, backend)` works without a client on Browser and Node. Kotlin and Swift use `SDKClient.canMessage` with an explicit backend. An existing client also has `canMessage`. Browser and Node return a `Map`; Kotlin and Swift return a dictionary keyed by the identity identifier.

## Create a group

The backend sets the group member limit. The default limit is 250 inboxes.

All four SDKs use `conversations.createGroup(members, options)`. Pass a list of inbox IDs or a list of `PublicIdentity` values. Do not mix the two in one list. Swift uses the labels `members:` and `options:`. Kotlin and Swift get the collection with `client.conversations()`.

Set the group name, description, image URL, app data, permissions, and disappearing-message settings at creation. See [Groups](/sdk/groups/).

## Optimistically create a group

Optimistic group creation enables you to prepare a group and messages before you know its members. The group stays only in the local database until you add a member. It is not visible to anyone else before that step.

All four SDKs use `createGroupOptimistic(options)`. The call is asynchronous. Add members, then call `publishMessages()` to publish prepared messages.

## Create a DM

Creating a DM returns the existing conversation if you already have one with that peer. You cannot create a DM with yourself.

All four SDKs use `conversations.createDm(peer, options)`. Pass an inbox ID or a `PublicIdentity` value. Swift uses the labels `peer:` and `options:`.

Different installations can create separate DMs for the same pair. XMTP stitches these records into one visible DM. A lookup can therefore return a different conversation ID. Do not key app state on a DM conversation ID. See [DM stitching](/sdk/push-notifications/#dm-stitching).

## Agent helpers

The Agent SDK adds `createDmWithAddress`, `createGroupWithAddresses`, and `addMembersWithAddresses`. `getSenderAddress()` resolves the first identifier for the sender and returns `undefined` when none exists.
