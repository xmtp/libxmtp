## Message list options

`messages()` returns enriched messages on all five platform SDKs. Each message includes reactions, a reply count, and its reply parent when available. There is no separate `enrichedMessages()` method.

| Option                                | Default    | Description                       |
| ------------------------------------- | ---------- | --------------------------------- |
| `limit`                               | None       | Maximum result count              |
| `sentBefore`, `sentAfter`             | None       | Filter by sent time               |
| `insertedBefore`, `insertedAfter`     | None       | Filter by local insertion time    |
| `sortBy`                              | Sent time  | Sort by sent or inserted time     |
| `direction`                           | Ascending  | Ascending or descending           |
| `deliveryStatus`                      | All        | Published, unpublished, or failed |
| `kind`                                | All        | Application or membership change  |
| `contentTypes`, `excludeContentTypes` | All / none | Include or exclude content types  |
| `excludeSenderInboxIds`               | None       | Exclude sender inbox IDs          |

Time filters use `Timestamp` values. A `Timestamp` has an `ns` field for nanoseconds. Pass `direction` when order matters.

`countMessages(options)` returns a count without loading messages. It accepts `ListMessagesOptions`, but ignores `limit`, `direction`, and `sortBy`.

### Reactions

`message.reactions` holds at most the 50 latest reaction messages to a message, oldest first. `reactionMessageCount` counts every unexpired reaction message to it, including removals and reactions that do not decode, so it is not a per-emoji tally. A UI that tallies from `message.reactions` undercounts a message with more than 50 reaction messages.

To read the rest, call `conversation.messageReactions(messageId, before, limit)`. It returns reaction messages newest first, at most `limit` (1 to 1000, default 50). For the next page, pass the last returned reaction's ID as `before`. If that reaction expires or is deleted between two calls, the call fails with `InvalidArgument`; start again from the newest reaction.

### Paginate messages

By default, messages are sorted by `sentAt`. A message can arrive after a newer message. The timestamp-filter examples below use `insertedAt` for local insertion order. The React Native example uses `messageHistoryPage` to paginate Published history by sent time and local delivery order with an opaque position.

A timestamp-only cursor can skip messages that have the same timestamp at a page boundary. For recent history followed by live delivery, use a [message history snapshot and delivery cursor](/sdk/stream/). A snapshot is a bounded recent tail. To replay all retained delivery history, start an independent reader at `client.conversations.beginningDeliveryCursor()` in each SDK.

## List conversations

We recommend listing allowed conversations only. This ensures that spammy conversations don't appear in the main inbox.

| Method                              | Returns        |
| ----------------------------------- | -------------- |
| `conversations.list(options)`       | Groups and DMs |
| `conversations.listGroups(options)` | Groups only    |
| `conversations.listDms(options)`    | DMs only       |

| Option                                    | Default             | Description                          |
| ----------------------------------------- | ------------------- | ------------------------------------ |
| `consentStates`                           | Allowed and unknown | Consent states to include            |
| `kind`                                    | Both                | Groups or DMs                        |
| `limit`                                   | 100                 | Maximum result count, 1 to 1000      |
| `orderBy`                                 | Last activity       | Creation or last activity            |
| `createdBefore`, `createdAfter`           | None                | Creation-time bounds                 |
| `lastActivityBefore`, `lastActivityAfter` | None                | Last-activity bounds                 |
| `beforeId`                                | None                | Resume after this conversation       |
| `includeDuplicateDms`                     | `false`             | Include every underlying stitched DM |

These options are available on all five platform SDKs. Time bounds use `Timestamp` values. A list returns at most 100 conversations when you pass no `limit`. A `limit` below 1 or above 1000 fails with `InvalidArgument`.

### Paginate conversations

A list returns conversations newest first, by listing time and then by conversation ID. To read every conversation once, set `orderBy` to creation time. For the next page, pass the last conversation's `createdAt` as `createdBefore` and its ID as `beforeId`. A time alone skips conversations that share the boundary time.

In last-activity order, pass the last conversation's `lastActivityAt()` as `lastActivityBefore` and its ID as `beforeId`. A conversation whose activity changes between two pages, because a message arrives or expires, can be returned twice or skipped.

Creation order can also return a DM twice or skip it when a message in another group of the same DM changes which group the list shows. A restored group whose Welcome arrives between two pages can be skipped. `beforeId` without the before time that matches `orderBy` fails with `InvalidArgument`.

`lastActivityAt()` with no content types ignores expired disappearing messages, so it is the time a last-activity list sorts by.

:::warning[Do not use with streaming]
Do not paginate a conversation list while a conversation stream adds items to that same list. Keep the stream and paginated result separate until pagination ends.
:::
