Start with [Migrate to a self-hosted backend](/get-started/migrate-to-self-hosted/)
for the backend, database, history, and push steps. This guide lists changes
from [`main` at `cc878025da`](https://github.com/xmtp/libxmtp/tree/cc878025dab2f93bca18b67fa9fca562a65f2247)
to [`self-hosted` at `610175f3b3`](https://github.com/xmtp/libxmtp/tree/610175f3b3108e7d8c6b8b01df6d99296a6e08b2).
A call can keep its name and still have different parameters, results, or
behavior. The **Before** examples use the old SDK. The **After** examples use
the new SDK.

The package name stays `@xmtp/browser-sdk`. The self-hosted SDK uses ESM and generated public bindings. Its source moved from `sdks/js/browser-sdk` to `sdks/browser`. Remove imports from `@xmtp/wasm-bindings` and private package paths. Import client types from `@xmtp/browser-sdk`. Import standalone codecs and pure helpers from `@xmtp/browser-sdk/pure`.

## Create a client and adapt the signer

The old signer used `type`, `getIdentifier()`, and `signMessage()`. The new signer uses asynchronous `identity()`, `kind()`, and `sign(request)`. The signature result names its kind. Replace `Identifier.identifierKind` with `PublicIdentity.kind`.

Old API on main:

```text title="Before (main cc878025da)"
import { Client, IdentifierKind, type Signer } from "@xmtp/browser-sdk";

async function createClient(
  address: string,
  signText: (text: string) => Promise<Uint8Array>,
) {
  const signer: Signer = {
    type: "EOA",
    getIdentifier: () => ({
      identifier: address,
      identifierKind: IdentifierKind.Ethereum,
    }),
    signMessage: signText,
  };
  return Client.create(signer, { env: "dev", appVersion: "chat/1.0" });
}
```

Use an explicit backend URL. `env`, `apiUrl`, and `gatewayHost` no longer select the network. The Browser SDK also requires `storage`. `Client.create(signer, options)` can establish an identity. `Client.build(identity, options, inboxId?)` opens a stored identity. An empty database fails with `IdentityNotFound` when opened with `build`.

For a smart contract wallet, return `{ kind: "scw", chainId, blockNumber }` from `kind()`. Return `{ kind: "scw", bytes, address, chainId, blockNumber }` from `sign()`. The optional block number and the chain ID use `bigint`. The new signer also supports the `passkey` kind. Remove `createEOASigner`, `createSCWSigner`, and `toSafeSigner` calls. Supply the new signer interface, or use `generateLocalSigner()` or `localSignerFromPrivateKey()` for an app-owned local key.

| `env`, `apiUrl`, `gatewayHost`                            | `backend: { url }`. There is no environment-to-URL lookup.                                                                                                                      |
| `backend: Backend`                                        | `backend: BackendSource`, with a connected `Backend` or `{ url, appVersion?, credentials? }`. `Backend.connect(options)` replaces `createBackend(options)` and the old builder. |
| `appVersion`                                              | `backend.appVersion` when using backend options.                                                                                                                                |

| `dbPath: string`                                          | `storage: { location: { dbPath, attachmentsDir } }`. Both OPFS entry paths are required.                                                                                        |
| `dbEncryptionKey`                                         | Removed from the Browser API. Browser storage has no SDK database encryption key. The new SDK rejects `storage.encryptionKey` with `StorageLocation`; it does not ignore it.    |

| `historySyncUrl`                                          | Removed. There is no archive-server URL option.                                                                                                                                 |
| `workerConfig`                                            | `workers`, with `defaultIntervalNs` and per-worker `intervals` records.                                                                                                         |
| `codecs`                                                  | Still per client, with the new public `ContentCodec` interface.                                                                                                                 |
| `loggingLevel`, `structuredLogging`, `performanceLogging` | Use the public logging configuration and `setLogSink()`. These are no longer client options.                                                                                    |

## Reopen an OPFS database after migration

The new SDK cannot open a pre-transition database. First create a new database on the target backend with `Client.create`. The examples below compare the reopen APIs; the new example requires a database already created by the new SDK. Old `client.close()` is synchronous. The new shutdown is `await client.end()`. Do not open two clients on one database at the same time.

Old API on main:

```text title="Before (main cc878025da)"
import { Client, type Identifier } from "@xmtp/browser-sdk";

async function reopen(identity: Identifier, oldDbPath: string) {
  const client = await Client.build(identity, { dbPath: oldDbPath });
  client.close();
}
```

Use the new database's actual OPFS entry name for `dbPath` and its attachment directory. Browser paths name OPFS entries; they are not host filesystem paths. The old default was `xmtp-{env}-{inboxId}.db3`. The new default uses the `xmtp-sdk` OPFS pool and a deployment/inbox layout. A default location does not move or convert an old database.

With default or directory storage, offline startup needs the saved backend deployment mapping and the saved inbox ID passed to `build`. Explicit paths do not need that path lookup. `allowOffline: true` permits startup from stored state. It does not prove that the backend used later is compatible.

`Storage.admin()` replaces `Opfs.create()`. It opens an independent lease on the package storage worker. Await `admin.end()` after use. There is no separate `init()` call.

Old API on main:

```text title="Before (main cc878025da)"
import { Opfs } from "@xmtp/browser-sdk";

async function exportDatabase(path: string) {
  const opfs = await Opfs.create();
  try {
    return await opfs.exportDb(path);
  } finally {
    opfs.close();
  }
}
```

## Create, find, and list conversations

`Conversation` is now a TypeScript union of `Group | Dm`. It is no longer a base class that an app constructs. Narrow it with `instanceof Group` or the `kind` property. Group and DM methods remain on their objects.

Old API on main:

```text title="Before (main cc878025da)"
import {
  ConversationType,
  IdentifierKind,
  type Client,
} from "@xmtp/browser-sdk";

async function createConversations(client: Client, address: string) {
  const peer = { identifier: address, identifierKind: IdentifierKind.Ethereum };
  const dm = await client.conversations.createDmWithIdentifier(peer);
  const group = await client.conversations.createGroupWithIdentifiers([peer], {
    groupName: "Team",
  });
  const listed = await client.conversations.list({
    conversationType: ConversationType.Group,
    limit: 20n,
  });
  return { dm, group, listed };
}
```

`updateGroupDescriptionPolicy`, `updateGroupImageUrlSquarePolicy`,
`updateMessageDisappearingPolicy`, and `updateAppDataPolicy` to `updateName`,
`updateDescription`, `updateImage`, `updateDisappearing`, and `updateAppData`.
Use the new string policy values in each field.

## Send and read messages

The standard send method names remain. All sends use `SendOptions`. The `optimistic` option remains available. `prepareMessage()` stores an unpublished message and queues optimistic publication. It does not keep an app draft private until a later publish call. `idempotencyKey` remains available on the new send options. Compression is optional and uses `"deflate"` or `"gzip"`. If a send fails with `PublishedButUnconfirmed`, call `conversation.sync()` before deciding what to do next. Do not immediately send the content again.

Old API on main:

```text title="Before (main cc878025da)"
import type { Conversation } from "@xmtp/browser-sdk";

async function sendMessages(conversation: Conversation) {
  const id = await conversation.sendText("Hello");
  await conversation.sendMarkdown("**Hello**");
  await conversation.sendReadReceipt();
  const pending = await conversation.sendText("Send later", {
    optimistic: true,
  });
  await conversation.publishMessages();
  return { id, pending };
}
```

## Replace `DecodedMessage` and content guards

`DecodedMessage<ContentTypes>` is replaced by `Message`. Its `content` is a tagged union. Check `message.content.kind` before reading a variant. The SDK does not use the old generic content union or the exported `isText`, `isReply`, and related guard helpers.

```text title="Before (main cc878025da)"
import { isText, type DecodedMessage } from "@xmtp/browser-sdk";

function display(message: DecodedMessage) {
  return isText(message) ? (message.content ?? "") : (message.fallback ?? "");
}
```

## Replace streams and save delivery progress

Use `MessageStream` for durable message delivery. Use `ConversationStream` for joined or created conversations. Both implement asynchronous iteration. They open without an awaited static factory call. Client events use `await client.events(filter)`.

The all-conversation message reader defaults to allowed and unknown consent. An explicit consent list replaces that default. An empty list selects no messages. A named group or DM reader has no consent filter. The selection remains fixed for the life of a reader.

One default message reader owns delivery progress for a database. Another default reader fails with `ConsumerOwned`, even when it selects a different group. A reader with `from` is an independent replay/live reader. It does not change default delivery progress.

The next iterator request acknowledges the previous message. Await app work before the next request. A successful `onValue` callback return acknowledges the delivered message. Loop exit, cancellation, `return()`, and `end()` do not acknowledge the last yielded message. Save a cursor only after successful app work. Deduplicate repeat work by message ID when needed.

Use `messageHistorySnapshot(limit, selection)` when a history query and live delivery need one boundary. The example reads up to 100 retained messages, then starts replay strictly after the snapshot cursor. Choose the history limit for the app. This is a local retained-history snapshot; it is not a request for all historical backend messages.

Catalogue content types have defined push defaults. Read receipts, reactions, group updates, deletion, and leave requests default to no push. An explicit `SendOptions.shouldPush` wins. A custom codec's hook does not replace the default for a catalogue type.

An encrypted-content helper result uses `{ ciphertext, keys }`. The keys record has `secret`, `salt`, `nonce`, `digest`, and `length`. `encryptEncodedContent` accepts serialized envelope bytes. `decryptEncodedContent` returns serialized envelope bytes. These are not the old attachment helper records.

The new attachment API adds `client.attachments` for upload, download, status, and deletion. Browser path sources refer to OPFS. Byte sources copy the caller's bytes at the Browser boundary. Transfer failures preserve a typed attachment cause; the SDK does not add automatic transfer retries.

The new API also adds backend configuration reads, credentials, catch-up state, metadata field descriptors and values, user data, client events, and message actions. These have no direct old Browser method to rename.
