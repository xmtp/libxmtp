Start with [Migrate to a self-hosted backend](/get-started/migrate-to-self-hosted/)
for the backend, database, history, and push steps. This guide lists changes
from [`main` at `cc878025da`](https://github.com/xmtp/libxmtp/tree/cc878025dab2f93bca18b67fa9fca562a65f2247)
to [`self-hosted` at `73636909dd`](https://github.com/xmtp/libxmtp/tree/73636909ddabfae64e370375ef8227c58f2abc5a).
A call can keep its name and still have different parameters, results, or
behavior. The **Before** examples use the old SDK. The **After** examples use
the new SDK.

## Node package and value types

Keep the package name `@xmtp/node-sdk`. SDK 8 requires ESM and Node 22.12 or later.
Use `import` instead of `require`. Build the current package before checking your
app. The old `@xmtp/node-bindings` package is not the public SDK 8 API.

The **previous** examples below use
[`main` at `cc878025d`](https://github.com/xmtp/libxmtp/tree/cc878025dab2f93bca18b67fa9fca562a65f2247/sdks/js/node-sdk/src).
They were checked against that source. The **current** examples use the local
SDK 8 declarations and are checked as complete TypeScript programs.

| Previous value                                                                                                  | Current value                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Identifier` with `identifierKind: IdentifierKind.Ethereum`                                                     | `PublicIdentity` with `kind: "ethereum"`. Use `"passkey"` for a passkey. The `identifier` field remains a string.                                                                                        |
| Numeric enum imports such as `ConsentState.Allowed`, `DeliveryStatus.Published`, and `SortDirection.Descending` | String values such as `"allowed"`, `"published"`, and `"descending"`. Import the type when you need a type annotation.                                                                                   |
| `ConversationType`, `GroupMessageKind`, `SortDirection`, `ListConversationsOrderBy`                             | Types `ConversationKind`, `MessageKind`, `MessageOrder`, `ConversationOrder`. Values use lower camel case, such as `"dm"`, `"membershipChange"`, and `"lastActivity"`.                                   |
| Nanosecond fields ending in `Ns`, with a separate `Date` getter                                                 | `Timestamp`. Use `.ns` for a `bigint`, `.date` for a `Date`, and `new Timestamp(ns)` for an input. This applies to message, conversation, identity, archive, and action times.                           |
| Mutable records and binding classes                                                                             | Read-only public records. IDs remain strings. Byte buffers are `Uint8Array`. Maps are `Map`, not plain JavaScript objects.                                                                               |
| Generic `Client<T>`, `Group<T>`, `Dm<T>`, `Conversation<T>`, and `DecodedMessage<T>`                            | Classes `Client`, `Group`, `Dm`, and `Message`. `Conversation` is the type `Group \| Dm`. Narrow a conversation with `instanceof Group` or `instanceof Dm`. Narrow received content with `content.kind`. |
| Direct `new Client(...)`, `client.init(...)`, or direct conversation/message constructors                       | Use `Client.create`, `Client.build`, and SDK lookup or creation methods. Public SDK objects have private constructors.                                                                                   |

## Signers and client setup

A signer has three asynchronous methods: `identity()`, `kind()`, and
`sign(request)`. Replace `type`, `getIdentifier`, and `signMessage`.

Previous EOA signer:

```text title="Before (main cc878025da)"
import { IdentifierKind, type Signer } from "@xmtp/node-sdk";

export function createSigner(
  address: string,
  signText: (text: string) => Promise<Uint8Array>,
): Signer {
  return {
    type: "EOA",
    getIdentifier: () => ({
      identifier: address,
      identifierKind: IdentifierKind.Ethereum,
    }),
    signMessage: signText,
  };
}
```

Passkey signers are also supported. Their identity uses `kind: "passkey"`;
`kind()` returns `{ kind: "passkey" }`; `sign()` returns a `"passkey"` signature
with `signature`, `publicKey`, `authenticatorData`, and `clientDataJson` byte
buffers. `generateLocalSigner()` and `localSignerFromPrivateKey(bytes)` are new
helpers for local Ethereum signers.

`Client.create(signer, options)` and `Client.build(identity, options, inboxId?)`
require an options object. `build` reopens a client without storing a signer.
Its optional third argument selects the inbox explicitly. SDK 8 can use the
inbox stored in explicit storage. `allowOffline: true` permits startup from
stored state when the backend is unavailable. It does not supply the data needed
for a first registration.

`backend.credentials` accepts a `Credential` or a source with asynchronous
`credential()`. A credential has `value`, signed 64-bit `expiresAtSeconds` in Unix
seconds, and optional header `name`. Use `client.setCredential(credential)` to
replace a supplied credential. `handlers.preAuthenticate` accepts a callback
with asynchronous `run()` for work that must precede authentication. `forkRecovery`
selects a policy (`"none"`, `"allowlistedGroups"`, or `"all"`), group IDs, whether
to disable responses, and an optional worker interval. `attachments` can set
`maxDownloadBytes`, `maxPendingAgeSeconds`, and `allowPrivateNetwork`. `Client.fetchServerConfiguration(backend)`
fetches configuration without a client. `client.serverConfiguration` is a
property; `await client.refreshServerConfiguration()` returns refreshed
configuration. Deployment limits and retention counts use `bigint`.

## Conversations, groups, and state

Creation methods accept inbox IDs or identities through one public method.
Do not mix strings and identities in one member list.

Previous creation:

```text title="Before (main cc878025da)"
import { Client, IdentifierKind } from "@xmtp/node-sdk";

export async function createConversations(client: Client, address: string) {
  const peer = { identifier: address, identifierKind: IdentifierKind.Ethereum };
  const dm = await client.conversations.createDmWithIdentifier(peer);
  const group = await client.conversations.createGroupWithIdentifiers([peer], {
    groupName: "Project",
    groupDescription: "Project chat",
  });
  const draft = client.conversations.createGroupOptimistic({
    groupName: "Draft",
  });
  await draft.addMembersByIdentifiers([peer]);
  return { dm, group, draft };
}
```
