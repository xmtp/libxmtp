---
title: React Native SDK Upgrade Guide
description: Migrate a pre-8.0.0 React Native app to the native v8 API and a self-hosted backend.
---

Every pre-8.0.0 React Native app must migrate. The npm package name remains
`@xmtp/react-native-sdk`; version **8.0.0-rc3** uses the generated native v8 API.
Existing method names, option shapes, generic types, hooks, and database files
are not a compatibility contract.

Start with [Migrate to a self-hosted backend](/get-started/migrate-to-self-hosted/).
All participants must use the same backend. Keep the other SDK and backend
version pins from that guide. Follow [React Native and
Expo](/get-started/react-native/) to configure Hermes, New Architecture, native
builds, and deployment floors.

This guide lists changes from
[`xmtp-react-native` v5.7.0](https://github.com/xmtp/xmtp-react-native/tree/f0a3d5ecec7552ee479de24b2f151db3e85fbb50)
to `@xmtp/react-native-sdk` 8.0.0-rc3, built from `sdks/react-native` in
`xmtp/libxmtp`. A call can keep its name and still have different parameters,
results, or behavior. The **Before** examples use v5.7.0. The **After** examples
use the v8 declarations and are checked as complete TypeScript programs.

## Upgrade the native package

Use SDK **8.0.0-rc3** with backend **8.0.0-rc3**:

```sh
npm install --save-exact @xmtp/react-native-sdk@8.0.0-rc3
```

Install iOS pods and rebuild the native app. Expo apps need a rebuilt development
client or prebuilt native project. Expo Go and JavaScript-only updates cannot
install the module. Import the public API from the package root and optional
React helpers from `/react`. Do not import generated binding paths.

Version 5.7.0 was an Expo module. Version 8 is a Hermes JSI TurboModule with
prebuilt Rust libraries. It requires Hermes and New Architecture. It no longer
needs `expo` as a peer dependency, and it does not accept a viem `WalletClient`
as a signer. Remove app imports from `@xmtp/proto`; v8 has its own
`EncodedContent` and `ContentTypeId` records.

## Recreate the client integration

| Area            | v8 integration                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend         | Pass `backend: { url }` or a `Backend`. Use the chosen deployment; there is no implicit public network.                                               |
| Signer          | Implement async `identity()`, `kind()`, and `sign(request)`, or restore a saved `LocalSigningKey`.                                                    |
| Storage         | Pass explicit `storage` options. Keep the optional 32-byte encryption key, location, and label stable. Default storage uses the native app directory. |
| Client creation | Use `Client.create(signer, options)` or reopen a current database with `Client.build(identity, options)`.                                             |
| Shutdown        | Await `client.end()` before external file operations.                                                                                                 |
| Types           | Use `Client`, `Group`, `Dm`, `Message`, and `Conversation` without legacy generic parameters.                                                         |
| Values          | IDs are strings; bytes are `Uint8Array`; maps are `Map`; full-width integers use `bigint`; times use `Timestamp`.                                     |
| Content         | Narrow `message.content.kind`. Standard codecs are built in; register only app custom codecs in `ClientOptions.codecs`.                               |
| Readers         | Use SDK message/conversation readers. Await app processing before the next value; close readers when their owner changes.                             |
| React           | Use `XmtpProvider`, `useXmtp`, and `useClient` from `/react`. No `setClient`, message hooks, or conversation hooks are exported.                      |
| Attachments     | Use `client.attachments` to create, upload, download, and manage native files. The app owns picking media and OS permissions.                         |
| Push            | Obtain tokens and OS permissions in the app, then call `client.enableNotifications`. Rewrite native handlers for the current push payload.            |

The sections below give the call-by-call changes. The TypeScript shapes match
the [Node SDK Upgrade Guide](/get-started/migrate-to-self-hosted/node-sdk-upgrade-guide/),
with mobile storage and lifecycle integration. Use the [React Native API
reference](/reference/react-native-sdk/) for the exact exported declarations.

## Package and value types

| v5.7.0 value                                                                                                                                            | v8 value                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `new PublicIdentity(address, "ETHEREUM")` class that lowercases the identifier                                                                          | Plain `PublicIdentity` record `{ identifier, kind: "ethereum" }`. Use `"passkey"` for a passkey and `"handle"` for a [handle](/sdk/inboxes/#handles).                                               |
| Upper-case string values such as `"ETHEREUM"`, `"PUBLISHED"`, and `"DESCENDING"`                                                                        | Lower camel case strings such as `"ethereum"`, `"published"`, and `"descending"`.                                                                                                                   |
| `XMTPEnvironment` (`"local"`, `"dev"`, `"production"`)                                                                                                  | Removed. Pass the deployment URL in `backend`. Use `storage.label` if the app keeps separate databases per deployment.                                                                              |
| Branded `InboxId`, `InstallationId`, `ConversationId`, `MessageId`, and `ConversationTopic`                                                             | IDs remain strings. `InstallationId` values are hex strings.                                                                                                                                        |
| Nanosecond `number` fields such as `sentNs`, `insertedAtNs`, and `exportedAtNs`                                                                         | `Timestamp`. Use `.ns` for a `bigint`, `.date` for a `Date`, and `new Timestamp(ns)` for an input. Old `number` nanosecond values lose precision; v8 uses `bigint`.                                 |
| Plain objects keyed by string, such as `canMessage` and `getHmacKeys` results                                                                           | `Map`. Read entries with `.get(key)`.                                                                                                                                                               |
| Generic `Client<ContentTypes>`, `Group<ContentTypes>`, `Dm<ContentTypes>`, `Conversation<ContentTypes>`, `DecodedMessage<T>`, and `DecodedMessageV2<T>` | Classes `Client`, `Group`, `Dm`, and `Message`. `Conversation` is the type `Group \| Dm`. Narrow a conversation with `instanceof Group` or `conversation.kind`. Narrow content with `content.kind`. |
| `ConversationVersion.GROUP` / `.DM` and `conversation.version`                                                                                          | `conversation.kind` is `"group"` or `"dm"`.                                                                                                                                                         |
| Public constructors such as `new Client(...)`, `new Group(...)`, and `new DecodedMessage(...)`                                                          | Use `Client.create`, `Client.build`, and SDK lookup or creation methods. Public SDK objects have private constructors.                                                                              |
| `Client.codecRegistry` and `Client.register(codec)`                                                                                                     | Removed. Pass custom codecs in `ClientOptions.codecs`. Standard content types are built in.                                                                                                         |
| `emitter`, `EventTypes`, and `expo-modules-core` subscriptions                                                                                          | Removed. Use stream objects and `client.events(...)`.                                                                                                                                               |

## Signers and client setup

A signer has three asynchronous methods: `identity()`, `kind()`, and
`sign(request)`. Replace `getIdentifier`, `getChainId`, `getBlockNumber`,
`signerType`, and `signMessage`. `sign` returns signature bytes, not a hex
string, and v8 does not split an ECDSA signature for you.

Before:

```text title="Before (xmtp-react-native v5.7.0)"
import { PublicIdentity, type Signer } from "@xmtp/react-native-sdk";

export function createSigner(
  address: string,
  signText: (text: string) => Promise<string>,
): Signer {
  return {
    getIdentifier: async () => new PublicIdentity(address, "ETHEREUM"),
    getChainId: () => undefined,
    getBlockNumber: () => undefined,
    signerType: () => "EOA",
    signMessage: async (message) => ({ signature: await signText(message) }),
  };
}
```

Version 5.7.0 accepted a viem `WalletClient` and converted it. In v8, write a
`Signer` that calls the wallet and converts its hex signature to bytes. Passkey
signers return a `"passkey"` signature with `signature`, `publicKey`,
`authenticatorData`, and `clientDataJson` byte buffers, rather than the old
`SignedData` strings.

`backend.credentials` accepts a `Credential` or a source with asynchronous
`credential()`. A credential has `value`, `expiresAtSeconds` as a `bigint` in
Unix seconds, and an optional header `name`. Use `client.setCredential(credential)`

the next build.

## Conversations, groups, and state

Creation methods accept inbox IDs or identities through one method. Do not mix
strings and identities in one member list.

## Convert closed legacy history to an archive

A package update does not open or adopt the old database. Keep a recoverable
copy of the legacy database and its key. Close the legacy SDK before conversion.
Create a new current database for the target backend and identity, then convert
eligible history to an archive and import it:

```ts source="legacy-migration-react-native.ts" region="imports"

```

```ts source="legacy-migration-react-native.ts" region="migrate"

```

The native converter accepts legacy databases whose recorded migrations match
the checked legacy migration chain, including known prefixes it can advance.
The pinned chain comes from libxmtp `6a8e969785c62e0923cf3d8531aff4eaac3c91b7`:
64 migrations used by Node 6.1.0 and Browser 7.1.0; Android and iOS 4.10.0 have
62, and 4.11.0 have 64. A React Native package version alone does not prove
schema compatibility. Unknown, reordered, or changed migrations fail with
`MigrationUnsupportedSchema`. Retain the original database when conversion
fails. Do not describe this as support for every old React Native release.

Conversion works on a copy of a closed source and preserves the source. A source
lock produces `StorageBusy`; close every legacy connection first. The archive
contains eligible messages, conversation metadata, and consent. It excludes
installation keys, MLS secrets, attachment files, and messages with stored expiry
deadlines. Import does not restore the old installation or move its network
identity. Arrange account registration and conversation membership on the new
backend separately.

Supply a separate 32-byte archive key and an output path in app-accessible
storage. Keep the archive key separate from the archive file. Do not overwrite
the source with the output.

Only import archives from a trusted source. Import does not verify message
provenance or sender membership, and anyone with the key can forge history under
another sender. Legacy repeated-nonce archives have weakened confidentiality and
authentication; importing them cannot restore those guarantees.

See [Backups](/sdk/backups/) and the
[migration overview](/get-started/migrate-to-self-hosted/#keeping-history) for conversion errors,
archive limits, and restoration behavior.

## Update ownership and background work

The provider releases clients it creates and preserves caller-owned clients
passed through its `client` prop. Do not close a borrowed client in a hook
cleanup unless that component is its actual owner. `disconnect()` cancels a
pending initialization; a late result cannot publish into context. Handle
initialization and cleanup errors explicitly.

Use native lifecycle handling supplied by the SDK. A JavaScript `AppState`
listener cannot cover native cold starts or work after runtime teardown.
Background push and iOS extensions require native OS integration, bounded sync,
and coordinated access to app storage. See [Push
notifications](/sdk/push-notifications/) before shipping the receiver.
