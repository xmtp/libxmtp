Follow this tutorial to build a quickstart chat app with XMTP.

When you build your quickstart app, you will use a key pair to create an identity and register it with XMTP. This gives you an inbox ID, which is a stable identifier that serves as the destination for your messages.

## 2. Create a signer and client

The signer must return the account identifier and sign messages as bytes.
`backendUrl` is required. Use the URL of your running backend. These examples
create temporary identities for testing. Do not use their key lifecycle in a
production app: store the signer key and database encryption key securely and
reuse them with the same database on later launches.

The Browser and Node blocks come from compiled source files. They are checked
against the SDK types during the docs build. The mobile examples create a second
client so that the message recipient is registered on the same backend.

```kotlin
import android.content.Context
import java.security.SecureRandom
import uniffi.xmtp_sdk.*
import kotlinx.coroutines.NonCancellable
import kotlinx.coroutines.withContext

suspend fun createDemoClient(context: Context, backendUrl: String): SDKClient {
    val signingKey = generateLocalSigner()
    val keyBytes = ByteArray(32).also { SecureRandom().nextBytes(it) }
    return SDKClient.create(
        context = context,
        signer = signingKey,
        options = ClientOptions(
            backend = BackendSource.Options(BackendOptions(url = backendUrl)),
            storage = StorageOptions(StorageLocation.Default, encryptionKey = keyBytes),
        ),
    )
}

suspend fun withDemoClients(
    context: Context,
    backendUrl: String,
    run: suspend (SDKClient, SDKClient) -> Unit,
) {
    val client = createDemoClient(context, backendUrl)
    try {
        val recipient = createDemoClient(context, backendUrl)
        try {
            run(client, recipient)
        } finally {
            withContext(NonCancellable) { recipient.end() }
        }
    } finally {
        withContext(NonCancellable) { client.end() }
    }
}

// Run in a coroutine in your Android Activity.
withDemoClients(applicationContext, "https://xmtp.example.com") { client, recipient ->
    val group = client.conversations().createGroup(listOf(recipient.inboxId()))
    group.sendText("Hello everyone")
    client.messages().collect { message -> println("New message: $message") }
}
```

</TabItem>
<TabItem label="Swift">

Load each client's stored 32-byte database key before the calls below. Generate a
new key securely for a new database, store it securely, and reuse it on reopen.
Omitting the key selects unencrypted storage.

```swift
import Foundation
import XmtpSdk

func createDemoClient(backendUrl: String, databaseKey: Data) async throws -> SDKClient {
  let signer = await generateLocalSigner()
  return try await SDKClient.create(
    signer: signer,
    options: ClientOptions(
      backend: .options(options: BackendOptions(url: backendUrl)),
      storage: StorageOptions(location: .default, encryptionKey: databaseKey)
    )
  )
}

// Run from an async context, such as a SwiftUI task.
let backendUrl = "https://xmtp.example.com"
let client = try await createDemoClient(backendUrl: backendUrl, databaseKey: clientDatabaseKey)
let recipient = try await createDemoClient(backendUrl: backendUrl, databaseKey: recipientDatabaseKey)
```

## 3. Send a message

Create a conversation and send a text message. For Browser and Node, use the
inbox ID printed by a second running client on the same backend. Put the Kotlin
send and stream operations in the `withDemoClients` block. For Swift, use the
recipient client from the preceding step.

With XMTP, sending a message delivers it to the backend, but doesn't automatically update the local UI (unless you use [optimistic sending](/sdk/send-messages/#optimistically-send-messages)).
