Follow this tutorial to run a local XMTP backend and send a message from one
client to another.

Each client uses a key pair to create an identity and register it with the
backend. This gives the client an inbox ID, which is a stable identifier that
other clients send messages to.

You need [Docker](https://docs.docker.com/get-docker/) with Docker Compose. For
Browser and Node, you also need Node.js 22.18.0 or later.

## 1. Start a local backend

Run these commands in a terminal. They create a project directory, download the
Compose file, and start PostgreSQL and the XMTP backend:

```sh
mkdir xmtp-quickstart && cd xmtp-quickstart
curl -fsSL https://xmtp.org/quickstart/compose.yaml -o compose.yaml
docker compose up -d --wait
```

The last command returns when the backend is healthy. The backend URL is
`http://127.0.0.1:5050`. Use `127.0.0.1`, not `localhost`: some systems resolve
`localhost` to an IPv6 address that Docker does not forward.

<details>
<summary>The Compose file</summary>

```yaml title="compose.yaml"
# Local XMTP backend for the quickstart. Do not use it in production:
# it has no authentication and a fixed database password.
#
#   docker compose up -d --wait   start, and wait until the backend is healthy
#   docker compose logs backend   show the backend logs
#   docker compose down           stop, and keep the data
#   docker compose down -v        stop, and delete the data
#
# Clients connect to http://127.0.0.1:5050.
name: xmtp-quickstart

services:
  db:
    image: postgres:18.6
    environment:
      POSTGRES_USER: xmtp
      POSTGRES_PASSWORD: xmtp
      POSTGRES_DB: xmtp
    volumes:
      - db-data:/var/lib/postgresql
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -h 127.0.0.1 -U xmtp -d xmtp"]
      interval: 1s
      timeout: 3s
      retries: 30

  backend:
    image: ghcr.io/xmtp/backend:8.0.0-rc2
    depends_on:
      db:
        condition: service_healthy
    environment:
      XMTP_DATABASE_URL: postgres://xmtp:xmtp@db:5432/xmtp
      XMTP_CONFIG: |
        [server]
        identifier = "local.xmtp.quickstart"

        [database]
        url = "env:XMTP_DATABASE_URL"
    ports:
      # Loopback only. Change to "5050:5050" to reach it from another device.
      - "127.0.0.1:5050:5050"
    healthcheck:
      test: ["CMD", "/bin/grpc-health-probe", "-addr=127.0.0.1:5050"]
      interval: 1s
      timeout: 5s
      retries: 30

volumes:
  db-data:
```

</details>

This backend has no authentication. Do not expose it outside your computer.
See [Run the backend](/get-started/run-the-backend/) for a production
configuration.

<TabItem label="Kotlin">

The signer provides `identity()`, `kind()`, and `sign(request)`.
`SDKClient.generateKeys()` returns a local signing key that implements these
methods. This example creates two temporary clients on the same backend, sends a
message from one to the other, and streams messages. Replace the backend URL
with a URL that your device can reach.

```kotlin
import android.content.Context
import java.security.SecureRandom
import uniffi.xmtp_sdk.*
import kotlinx.coroutines.NonCancellable
import kotlinx.coroutines.withContext

suspend fun createDemoClient(context: Context, backendUrl: String): SDKClient {
    val signingKey = SDKClient.generateKeys()
    val keyBytes = ByteArray(32).also { SecureRandom().nextBytes(it) }
    return SDKClient.create(
        context = context,
        signer = signingKey,
        options = ClientOptions(
            backend = BackendSource.Options(BackendOptions(url = backendUrl)),
            storage = StorageOptions(StorageLocation.Default, encryptionKey = keyBytes),
        ),
    )
}

suspend fun withDemoClients(
    context: Context,
    backendUrl: String,
    run: suspend (SDKClient, SDKClient) -> Unit,
) {
    val client = createDemoClient(context, backendUrl)
    try {
        val recipient = createDemoClient(context, backendUrl)
        try {
            run(client, recipient)
        } finally {
            withContext(NonCancellable) { recipient.end() }
        }
    } finally {
        withContext(NonCancellable) { client.end() }
    }
}

// Run in a coroutine in your Android Activity.
withDemoClients(applicationContext, "https://xmtp.example.com") { client, recipient ->
    val group = client.conversations.createGroup(listOf(recipient.inboxId()))
    group.sendText("Hello everyone")
    client.conversations.streamAllMessages().collect { message -> println("New message: $message") }
}
```

The `withDemoClients` helper ends both clients when its block exits.

<TabItem label="Swift">

The signer provides `identity()`, `kind()`, and `sign(request)`.
`SDKClient.generateKeys()` returns a local signing key that implements these
methods. This example creates two temporary clients on the same backend, sends a
message from one to the other, and streams messages. Replace the backend URL
with a URL that your device can reach.

Load each client's stored 32-byte database key before the calls below. Generate a
new key securely for a new database, store it securely, and reuse it on reopen.
Omitting the key selects unencrypted storage.

```swift
import Foundation
import XmtpSdk

func createDemoClient(backendUrl: String, databaseKey: Data) async throws -> SDKClient {
  let signer = await SDKClient.generateKeys()
  return try await SDKClient.create(
    signer: signer,
    options: ClientOptions(
      backend: .options(options: BackendOptions(url: backendUrl)),
      storage: StorageOptions(location: .default, encryptionKey: databaseKey)
    )
  )
}

// Run from an async context, such as a SwiftUI task.
let backendUrl = "https://xmtp.example.com"
let client = try await createDemoClient(backendUrl: backendUrl, databaseKey: clientDatabaseKey)
let recipient = try await createDemoClient(backendUrl: backendUrl, databaseKey: recipientDatabaseKey)

let group = try await client.conversations.createGroup(members: [recipient.inboxId()])
try await group.sendText(text: "Hello everyone", options: nil)

for try await message in try await client.conversations.streamAllMessages() {
  print("New message: \(message)")
}
```

When you stop the stream, call `try await recipient.end()` and
`try await client.end()`.

## How it works

- `streamAllMessages()` delivers messages from every conversation, including
  conversations that start after the stream opens. The default consent filter
  includes `allowed` and `unknown` conversations. A conversation that another
  inbox starts is `unknown` until you allow it. If you pass
  `consentStates: ["allowed"]`, the stream skips those messages. See
  [Consent](/sdk/consent/).
- When the stream opens, it also delivers messages that arrived while the client
  was offline. You do not need to call `syncAll` before you stream. Use
  [sync](/sdk/sync/) to refresh conversation and message lists that you read
  without a stream.
- These examples use new keys and in-memory databases, so each run is a new
  inbox. A real app must
  [save and restore its signing key](/sdk/signer/#save-and-restore-a-local-key)
  and keep the same database between launches. In Node, pass a 32-byte
  `storage.encryptionKey` to encrypt the database.
- Sending a message stores it locally and publishes it to the backend. See
  [optimistic sending](/sdk/send-messages/#optimistically-send-messages) to show
  a message before publication completes.

## Stop the backend

Run these commands in the `xmtp-quickstart` directory:

```sh
docker compose down     # stop, and keep the data
docker compose down -v  # stop, and delete the data
```
